# FinSight 产品定位文档 v1

## 一句话定位

> **帮散户在 5 分钟内,看清一只票的"基本面"和"舆论面",做出不被情绪裹挟的决策。**

---

## 1. 目标用户

**主用户**:中级散户

| 维度 | 画像 |
|---|---|
| 年龄/股龄 | 28-45 岁,股龄 1-5 年 |
| 资金量 | 本金 5-50 万 |
| 行为 | 自选股 5-30 只,白天上班、盘前盘后看盘 |
| 能力边界 | **会**:看 K 线、读 PE/PB、知道行业;**不会**:做 DCF、查原始公告、读财报附注 |
| 信息源 | 雪球、东方财富、抖音财经号、券商 App、研报截图 |
| 心理状态 | 想理性但容易追涨杀跌、信大V又怕被割、想自己判断又没时间 |

**次用户**:投资新手(0-1 年股龄),想通过看 AI 怎么分析学会自己分析

**明确不服务**:专业研究员、机构投资者、量化用户、纯小白(连 K 线都不会看)

---

## 2. 用户三大痛点(按严重度排序)

### 痛点 1:**舆论过载,不知道信谁**

同一只票同时存在 4-5 种声音:
- 雪球大V 看多 vs 财经媒体看空
- 抖音股评喊冲 vs 研报维持中性
- 散户社区一片狂欢 vs 北向资金净流出

**用户花 30 分钟刷完,反而更迷茫。** 缺一个**聚合 + 提炼 + 标识可信度**的角色。

### 痛点 2:**数据会查,但不会读**

"茅台 PE 27 倍"——是高?是低?
- 历史分位多少?
- 同业对标是几倍?
- 这个数据该怎么影响我的决策?

用户**知道 PE 重要,不知道 PE 怎么用**。需要的不是数据,是数据 + 解读。

### 痛点 3:**情绪时刻没有反方声音**

看到涨停就追、看到大跌就割——是散户亏损的核心原因。
缺的不是数据,是**在情绪上头时被强制看一眼反方逻辑**。

---

## 3. 核心价值主张

> **"5 分钟,三视角:基本面 × 舆论面 × 多空对辩"**

| 视角 | 解决的痛点 | 对应产品能力 |
|---|---|---|
| **基本面** | 痛点 2 — 数据会查不会读 | 行情快照 + 财务因子 + 历史走势 + **AI 解读** |
| **舆论面** | 痛点 1 — 舆论过载 | 公告 + 新闻 + 网络搜索 + 热榜,**AI 提炼共识与分歧** |
| **多空对辩** | 痛点 3 — 缺反方视角 | 观点卡的 debate_points,**强制呈现对立逻辑** |

**关键差异化**:业界产品要么只做数据查询(i 问财),要么只做社区情绪(雪球),**FinSight 是把"舆论怎么说"作为一等公民、和基本面并列分析的工具**。

## 4. 典型用户故事

### 故事 1:盘前 8:45 — 追涨场景
> 老王看到 AI 板块要爆发,想追寒武纪。
>
> 打开 FinSight 问"寒武纪今天能追吗"——10 秒拿到观点卡:
> - **基本面**:PE 历史分位 99%(贵)
> - **舆论面**:近 7 日新闻 80% 多头、机构买方共识"中性"、近 30 天 3 次大股东减持公告
> - **多空对辩**:左多右空一目了然
>
> 决定**不追**,去喝早茶。

### 故事 2:盘后 15:30 — 异动复盘
> 小李持仓的兆易创新今天突然大跌 6%。
>
> 问"兆易创新今天为什么跌"——
> - **舆论面**:当日有大客户砍单传闻 + 1 条减持公告
> - **基本面**:估值仍在中位
> - **多空对辩**:短期利空已 priced,但解禁压力未释放
>
> 决定**持有观察一周**。

### 故事 3:盘前 8:30 — 自选股 brief(扩展场景)
> 张姐打开 FinSight,看到自选股有一条主动推送:
> - 某公司发了解禁公告
> - AI 标识"短期偏空,建议关注下周一开盘表现"
>
> **被动接收"该看的"信息,不用每天主动问。**

## 5. 产品能力地图

```
入口
├── 自由提问                "茅台怎么样"
├── 自选股盘前 brief        每天 8:30 主动推送(规划中)
└── 热股诊断                hot_list 自动挑 3 只(规划中)

核心能力(对应 12 个工具 + 4 个 Skill)
├── 基本面分析
│   └── get_stock_profile / get_price_snapshot / get_financial_factors / get_daily_bars
├── 舆论面聚合
│   └── search_announcements / search_news / search_web / get_hot_list
└── 多空对辩
    └── commit_opinion (stance + debate_points + evidence_chain)

输出
├── 观点卡                  一句话结论 + 多空逻辑 + 证据链
├── 信息溯源                每条结论可追到原始数据
└── 决策动作(规划中)       加入观察 / 设提醒 / 标记决策
```

## 6. 竞争格局与差异化

| 产品 | 服务谁 | 强项 | FinSight 差异化 |
|---|---|---|---|
| **雪球** | 散户社区 | UGC + 大V观点 | FinSight 聚合舆论但**不是社区**,避免信息茧房和大V带节奏 |
| **同花顺 i 问财** | 散户查数据 | 自然语言数据查询 | FinSight 出**观点和判断**,不只是返回数据表格 |
| **通用 ChatGPT** | 通用问答 | 推理强 | FinSight 接 A 股实时数据 + ST 名单 + 历史回测,**领域 Agent vs 通用 Agent** |
| **券商研报** | 机构散户共用 | 深度分析 | FinSight 实时 + 中立,**不绑某家券商持仓利益** |
| **抖音财经号** | 散户娱乐化 | 情绪带动 | FinSight 提供**反节奏声音**,是抖音的解药 |

**真正的护城河**:把"舆论作为一等公民"是其他产品**不敢做**的——传统财经产品怕被定义为"情绪化"。但散户决策的真实逻辑本来就是**基本面占一半、舆论占一半**——**承认这一点反而是产品的诚实**。

## 7. 指标体系

### 北极星指标

**W1 回访率**(用户首次使用后 7 天内是否再回来)

为什么不是 DAU、问答数:散户工具不是聊天产品,看一眼就走也是价值。回访 = 上次体验有用。

### 一级指标(用户旅程 5 段)

| 阶段 | 指标 | 目标 |
|---|---|---|
| 激活 | TTV (首问→第一张观点卡) | < 30s |
| 价值 | **观点方向 T+5 命中率** | > 55% (baseline 50%) |
| 信任 | "加入观察"点击率 | > 25% |
| 效率 | 一次到位率(无追问完成) | > 50% |
| 留存 | W1 / W4 回访 | 30% / 15% |

### 护栏指标(零容忍 / 区间约束)

| 指标 | 阈值 | 为什么 |
|---|---|---|
| ST/退市股漏报率 | = 0% | 合规红线 |
| 强结论占比 | 20%-40% | 防"装权威" |
| "我不知道"输出率 | 5%-15% | 防"装懂"也防"过度怂" |
| 免责声明覆盖率 | 100% | 合规必须 |
| Injection 抗 stance flip | = 0% | 防舆论被操纵 |

## 8. 产品边界(不做什么)

| 不做 | 为什么 |
|---|---|
| ❌ 交易撮合 | 合规 + 不是核心价值,用户已有券商 App |
| ❌ 组合管理 | 同上,且会泄露用户敏感数据 |
| ❌ 社交 / UGC | 一旦做社区就和雪球同质化,信息茧房风险 |
| ❌ 实时盯盘 | 工具不是要让人盯一天,是盘前盘后两次决策辅助 |
| ❌ 给具体买卖价位 | 合规红线——AI 给点位 = 投资建议 = 牌照问题 |
| ❌ 多 Agent 协调 | 当前业务规模不需要,过度工程 |

**核心原则**:**做工具,不做平台**。

---

## 9. 商业化(放在最后,因为不该是 demo 阶段焦点)

**当前阶段**:不考虑商业化,先证明产品价值能成立。

**未来可行路径**(优先级排序):
1. **订阅制**:盘前 brief + 自选股事件推送作为付费 hook(~19 元/月)
2. **券商合作**:嵌入券商 App 作为客户增值服务,B2B2C
3. **付费版功能**:回测准确率仪表盘、深度公司分析、研报对比

**不走广告变现路径**——投研产品的信任比流量值钱 100 倍。

## 10. 验证 roadmap(下一步)

| 周次 | 动作 | 验证什么 |
|---|---|---|
| W1 | 访谈 20 个中级散户 | "舆论焦虑"是不是真痛点 |
| W2-3 | 拉 5 个真实用户用 2 周 | W1 回访率能不能跑过 30% |
| W3-4 | 跑 200 条 backtest | T+5 命中率能不能跑过 55% |
| W4 | 决定是否放量 | 三个数据全部达标才放量 |

**前置原则**:**用户访谈推翻定位假设时,改定位优先于改功能**——这是评测先于设计的产品层应用。
